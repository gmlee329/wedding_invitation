# 모바일 청첩장 설계

## 1. 목표와 성공 기준

참고 사이트의 에디토리얼 웨딩 매거진 분위기와 긴 세로형 모바일 흐름을 참고하되, 저작물과 디자인을 그대로 복제하지 않는 독립적인 모바일 청첩장을 만든다.

완성본은 다음 조건을 만족해야 한다.

- 실행 코드는 루트의 `index.html` 한 파일에만 둔다.
- 빌드 도구, 서버, 외부 라이브러리 없이 `index.html`을 직접 열어 확인할 수 있다.
- GitHub 공개 저장소와 GitHub Pages에 그대로 올릴 수 있는 상대 경로만 사용한다.
- 모든 이름, 날짜, 주소, 메시지, 연락처, 계좌, 링크, 미디어 경로는 `index.html` 상단의 `WEDDING_CONFIG` 객체에서 수정한다.
- 모든 주요 섹션은 `WEDDING_CONFIG.sections`의 불리언 값으로 표시 여부를 결정한다.
- 사진은 `assets/images`, 인트로 영상은 `assets/video` 아래 파일만 교체하면 된다.
- 영상이 존재하면 접근 직후 자동 재생하고, 종료 또는 `SKIP` 선택 시 본문으로 전환한다.
- 영상이 없거나 재생에 실패해도 방문자가 빈 화면에 갇히지 않고 본문을 볼 수 있다.
- 360px 안팎의 작은 모바일 화면부터 데스크톱까지 레이아웃이 깨지지 않는다.

## 2. 검토한 구현 접근법

### A. 상단 설정 객체 + 자바스크립트 렌더러 (채택)

한 개의 명확한 설정 객체를 데이터 원본으로 사용하고, 인라인 자바스크립트가 각 섹션을 만든다. 정보가 HTML 여러 곳에 중복되지 않고, 섹션 토글과 미디어 경로 교체가 가장 단순하다. 자바스크립트가 필요하지만 현재 요구 기능인 영상 전환, 달력, 카운트다운, 모달, 복사, 공유에도 어차피 필요하다.

### B. 모든 본문을 정적 HTML로 작성하고 CSS로 숨김

파일을 열었을 때 구조가 직관적이지만 이름·날짜·주소가 여러 위치에 반복되고, 섹션 표시 설정과 달력 같은 파생 정보를 동기화하기 어렵다. 사용자가 한 곳만 수정한다는 요구와 맞지 않아 제외한다.

### C. 별도 JSON 설정 파일 사용

데이터와 화면을 가장 깔끔하게 분리할 수 있지만, 실행 코드가 한 파일이어야 한다는 조건과 충돌하며 `file://`에서 `fetch`가 제한될 수 있다. 로컬 직접 열기 조건 때문에 제외한다.

## 3. 정보 구조와 화면 설계

전체 폭은 모바일에서 화면을 채우고, 넓은 화면에서는 약 460px의 초대장 본문을 중앙에 배치한다. 색상은 따뜻한 아이보리, 잉크 블랙, 세이지 그린, 브론즈 계열을 사용한다. 큰 세리프 제목과 절제된 산세리프 보조문구, 얇은 선, 종이 질감을 CSS만으로 표현한다.

섹션 순서는 다음과 같다.

1. 인트로 영상: 전체 화면 세로 영상, 어두운 그라데이션, 예식 영문 표기, 진행 표시, 음소거 토글, `SKIP` 버튼
2. 메인: 겹쳐진 큰 제목과 대표 사진, 신랑·신부 이름, 날짜
3. 초대의 글: 인사말과 혼주 관계
4. 신랑·신부 소개 및 연락: 두 사람과 양가 부모 연락처 모달
5. 예식 일정: 날짜·시간, 해당 월 달력, 실시간 D-day 카운트다운
6. 우리의 이야기: 연도별 타임라인
7. 갤러리: 반응형 사진 그리드와 전체 화면 라이트박스
8. 오시는 길: 장소, 주소, 전화, 지도 이미지, 내비게이션 링크
9. 교통 안내: 지하철·버스·주차 등 자유 텍스트
10. 안내 사항: 포토부스, 화환 안내 등 카드 목록
11. 마음 전하실 곳: 신랑측·신부측 계좌 아코디언과 복사 버튼
12. 공유: 기기 공유 기능 우선, 지원하지 않으면 주소 복사
13. 맺음말: 날짜·장소와 짧은 문구

인트로를 제외한 각 항목은 독립적인 `section`으로 렌더링되며 `sections` 설정이 `false`면 DOM에 만들지 않는다.

## 4. 설정 구조

`WEDDING_CONFIG`는 용도를 찾기 쉽도록 다음 그룹으로 나눈다.

- `sections`: 섹션별 표시 여부
- `theme`: 대표 색상과 초대장 최대 너비
- `intro`: 영상·포스터 경로, 영문 문구, 음소거 기본값, 오류 시 대기 시간
- `couple`: 신랑·신부 이름, 영문명, 전화번호, 부모 정보
- `wedding`: ISO 날짜·시간, 표시용 날짜, 예식장·홀·주소·전화
- `messages`: 메인 문구, 초대글, 맺음말
- `media`: 대표 사진, 갤러리 목록, 지도 이미지
- `story`: 타임라인 항목
- `transportation`: 교통 항목
- `notices`: 안내 카드
- `accounts`: 양가 계좌 목록
- `navigation`: 네이버지도·카카오맵·티맵 링크
- `sharing`: 공유 제목과 설명

사진 목록과 안내·계좌·타임라인은 배열 항목을 추가하거나 지우는 것만으로 개수를 바꿀 수 있게 한다.

## 5. 동작과 데이터 흐름

문서가 준비되면 다음 순서로 실행한다.

1. 설정값을 CSS 사용자 변수에 반영한다.
2. 켜진 섹션만 렌더링하고 표시 문자열은 `textContent` 중심으로 넣는다.
3. ISO 예식 날짜를 기준으로 달력과 카운트다운을 계산한다.
4. 인트로가 켜져 있으면 본문 스크롤을 잠그고 영상을 재생한다.
5. 영상 `ended`, `SKIP`, `Escape`, 또는 미디어 오류 시 동일한 `finishIntro()` 경로로 본문을 공개한다.
6. 갤러리, 연락처, 계좌, 공유 버튼 이벤트를 연결한다.
7. 스크롤 진입 시 섹션을 부드럽게 표시하되 `prefers-reduced-motion` 사용자는 즉시 표시한다.

계좌 복사와 공유 주소 복사는 보안 컨텍스트에서 `navigator.clipboard`를 사용하고, `file://` 등에서는 임시 입력 요소와 `execCommand('copy')`로 대체한다.

## 6. 오류와 예외 처리

- 인트로 영상이 없거나 디코딩되지 않으면 포스터 또는 CSS 배경을 보여주고 설정된 짧은 시간 뒤 본문으로 이동한다. 방문자는 즉시 `청첩장 보기`를 누를 수도 있다.
- 일반 사진이 없으면 깨진 이미지 아이콘 대신 번호와 안내 문구가 있는 디자인된 플레이스홀더를 유지한다.
- 잘못된 예식 날짜는 달력·카운트다운만 숨기고 나머지 초대장은 유지한다.
- 예식이 지난 경우 음수 카운트다운 대신 `오늘, 저희 결혼합니다` 또는 `함께 축복해 주셔서 감사합니다`를 표시한다.
- 전화번호, 계좌, 내비게이션 링크가 비어 있으면 해당 버튼만 만들지 않는다.
- 공유 API가 없거나 사용자가 공유를 취소하면 페이지는 그대로 유지하며, 취소가 아닌 오류일 때만 간단한 상태 메시지를 표시한다.

## 7. 접근성과 반응형

- 모든 버튼에 한국어 접근성 이름을 제공하고 키보드 초점 표시를 유지한다.
- 모달과 라이트박스는 `Escape`로 닫히며, 열릴 때 닫기 버튼으로 초점을 이동하고 닫을 때 원래 버튼으로 복원한다.
- 이미지에는 설정에서 생성한 대체 텍스트를 사용한다.
- 색상 대비, 최소 44px 터치 영역, `aria-live` 상태 메시지를 적용한다.
- 동작 감소 설정에서는 페이드·스크롤 애니메이션을 제거한다.
- 모바일 우선으로 작성하고 700px 이상에서는 페이지 바깥 배경과 그림자를 추가한다.

## 8. 검증 계획

- 파일 정적 검사: `index.html` 외부 스크립트·스타일 의존성, 절대 경로, 설정 밖 하드코딩 정보 여부를 확인한다.
- 자바스크립트 검사: 인라인 스크립트를 추출해 문법 오류가 없는지 확인한다.
- 브라우저 기능 검사: 모바일 크기에서 영상 오류 대체 흐름, 스킵, 섹션 토글, 달력, 갤러리, 모달, 계좌 복사, 공유 대체 동작을 확인한다.
- 반응형 검사: 360×800, 390×844, 넓은 데스크톱 화면에서 수평 넘침과 잘림을 확인한다.
- 접근성 검사: 키보드 이동, `Escape`, 축소 동작 설정, 주요 레이블을 확인한다.
- GitHub Pages 호환 검사: 모든 로컬 리소스가 `./assets/...` 상대 경로이고 네트워크 요청 없이 본문이 렌더링되는지 확인한다.

## 9. 범위 밖 항목

정적 페이지 제약을 지키기 위해 방명록 저장, 참석 여부 서버 전송, 사진 업로드 서버, 지도 SDK, 카카오톡 전용 JavaScript SDK는 포함하지 않는다. 대신 외부 지도 링크와 운영체제 공유 기능을 사용한다. 실제 사진·영상과 실명·연락처·계좌 정보는 사용자가 추후 설정과 미디어 폴더에서 교체한다.

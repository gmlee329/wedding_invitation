# 히어로 레이아웃·배경·모바일 모션 디자인

## 목표

첫 화면의 `Happily Ever After`가 어떤 모바일 높이에서도 메인 이미지와
겹치지 않게 한다. 제목과 메인 이미지는 히어로 섹션의 좌우 20px 콘텐츠
여백 안을 충분히 활용하고, 서로 같은 왼쪽 기준선에 맞춘다. 전체 배경은
청록기를 줄인 옅은 하늘빛 A안으로 바꾸고, 모바일 본문 등장 애니메이션을
인트로 종료 뒤 확실히 보이도록 복구한다.

## 확인된 원인

- 히어로 헤더의 `margin-bottom: -48px`가 짧은 화면에서 제목을 이미지 위로
  끌어내린다.
- 375×667 화면에서 제목과 이미지 영역이 약 42px 겹친다.
- 메인 이미지는 `width: calc(100% - 34px)`와 `margin-left: auto` 때문에
  콘텐츠 폭보다 34px 좁고 오른쪽으로 치우쳐 있다.
- 히어로 헤더의 좌우 14px 패딩 때문에 제목의 시작점이 섹션의 20px
  왼쪽 기준선보다 안쪽에 있다.
- 본문 reveal 관찰자가 인트로보다 먼저 시작되어 히어로가 인트로 뒤에서
  이미 `is-visible` 상태가 된다. 사용자가 본문을 볼 때는 애니메이션이
  끝나 있어 모바일에서 모션이 보이지 않는다.

## 검토한 접근

### A. 정상 흐름과 콘텐츠 폭 정렬 — 채택

- 헤더의 음수 하단 여백을 양수 간격으로 바꾼다.
- 헤더 좌우 패딩을 없애 섹션의 20px 왼쪽 기준선에 맞춘다.
- 제목을 가용 폭에 맞는 반응형 크기로 조정한다.
- 이미지를 히어로 콘텐츠 폭의 100%로 만든다.

짧은 화면에서도 구조적으로 겹칠 수 없고, 사용자가 요청한 왼쪽 정렬과
전체 콘텐츠 폭을 동시에 충족한다.

### B. 기존 겹침 구조에 고정 여백 추가 — 제외

음수 여백과 레이어 구조를 유지한 채 이미지 위쪽에 보정 여백을 넣는
방식이다. 화면 높이와 글꼴 렌더링에 따라 다시 겹칠 수 있어 제외한다.

### C. 이미지를 화면 끝까지 확장 — 제외

섹션의 좌우 20px 패딩을 상쇄해 완전한 풀 블리드 이미지로 만드는
방식이다. 사용자가 요청한 기존 왼쪽 여백 기준과 다르므로 제외한다.

## 최종 레이아웃

### 히어로 헤더

- 기존 상단 간격과 왼쪽 정렬을 유지한다.
- `margin: 0 0 32px`로 이미지와 명시적인 간격을 둔다.
- `padding: 30px 0 0`으로 좌우 안쪽 패딩만 제거한다.
- 현재 등장 애니메이션과 `z-index`는 유지한다.

### 히어로 제목

- Courgette와 한 줄 표기를 유지한다.
- `max-width: 100%`를 유지한다.
- `font-size: clamp(1.8rem, 10.5vw, 2.9rem)`으로 콘텐츠 폭을 더 충분히
  사용하되 320px 화면에서도 한 줄 전체가 보이게 한다.
- 현재 굵기, 자간, 행간과 색상은 유지한다.

### 메인 이미지

- `width: 100%`로 히어로 콘텐츠 폭을 채운다.
- `margin-left: 0`으로 왼쪽 20px 기준선에 맞춘다.
- 기존 종횡비, 이미지 크롭, 배경, 모서리와 대체 이미지 처리는 유지한다.

### Wedding Invitation 위치

- `Wedding Invitation`은 `Happily Ever After` 위에 유지한다.
- 헤더 전체를 정상 문서 흐름으로 돌려 두 문구 모두 이미지보다 위에 둔다.
- 제목과 이미지 사이 32px 간격으로 세 요소가 겹치지 않게 한다.

## 배경색과 사용자 편집 위치

- 사용자가 선택한 A안 `#f2f8ff`를 전체 배경으로 적용한다.
- 배경색은 CSS 상단 `:root`의 `--paper` 한 곳만 실제 소스로 사용한다.
- `WEDDING_CONFIG.theme.paper`와 `applyTheme()`의 `--paper` 덮어쓰기를 제거해
  `--paper`만 수정하면 전체 배경이 즉시 바뀌게 한다.
- `--paper` 선언 옆에 `전체 배경색: 이 값만 변경하세요` 주석을 둔다.
- 나머지 잉크, 초록, 하늘색, 세이지 색상은 유지한다.

## 모바일 등장 애니메이션

- reveal 초기화는 인트로가 완전히 제거된 뒤 한 번만 실행한다.
- 인트로가 비활성화되었거나 생성되지 않으면 reveal을 즉시 초기화한다.
- 중복 초기화를 막는 단일 불리언 상태만 추가하고 별도 모션 시스템은 만들지 않는다.
- 헤더 이동 거리는 52px, 지속시간은 1600ms로 늘린다.
- 본문 이동 거리는 44px, 지속시간은 1800ms, 지연은 260ms로 늘린다.
- 기존 easing과 `prefers-reduced-motion: reduce` 예외는 유지한다.

## 예시 메인 이미지

- 실제 인물과 닮지 않은 익명의 예비부부 뒷모습 중심 세로형 웨딩 사진을 생성한다.
- 자연광, 옅은 하늘빛과 세이지 그린이 어울리는 차분한 야외 분위기로 만든다.
- 이미지 안에는 글자, 로고, 워터마크를 넣지 않는다.
- 최종 예시 파일을 `assets/images/hero.jpg`에 저장한다.
- 현재 이미지가 없으므로 새 파일 추가이며 기존 원본을 덮어쓰지 않는다.

## 이미지 파일명 안내

- 상단 `WEDDING_CONFIG.media` 객체를 여러 줄로 펼치고 파일명 규칙을 주석으로 적는다.
- 메인 이미지는 `assets/images/hero.jpg`, 약도는 `assets/images/map.jpg`를 사용한다.
- 갤러리는 `assets/images/gallery-01.jpg`부터 `gallery-08.jpg`까지 두 자리
  번호 형식을 사용한다.
- 다른 파일명이나 확장자를 쓰면 `media` 객체의 해당 경로도 함께 수정해야 한다는
  예시를 주석에 포함한다.
- 런타임 로직이나 갤러리 개수는 변경하지 않는다.

## 유지 범위

- 배경색 외의 초록·하늘색 테마를 변경하지 않는다.
- 인트로와 영상 재생 동작, 나머지 섹션의 구조를 변경하지 않는다.
- 히어로 하단 이름·날짜 레이아웃과 문구를 유지한다.
- 예시 `hero.jpg` 외의 미디어 파일을 추가하거나 변경하지 않는다.
- `assets/video/intro.original.mp4`는 추적하거나 커밋하지 않는다.

## 검증

- CSS 회귀 테스트를 먼저 실패시켜 음수 여백, 축소 이미지 폭과 오른쪽
  정렬을 다시 도입할 수 없게 한다.
- 320×667, 375×667, 375×812에서 제목의 아래쪽이 이미지 위쪽보다 위에
  있는지 실측한다.
- 제목과 이미지의 왼쪽·오른쪽 경계가 히어로 콘텐츠 폭과 일치하는지
  확인한다.
- 제목이 한 줄이며 잘리지 않고 문서에 가로 넘침이 없는지 확인한다.
- 인트로가 열린 동안 히어로가 `is-visible`이 아니며, 인트로 제거 뒤 reveal이
  시작되는지 모바일 브라우저에서 확인한다.
- 헤더 1600ms, 본문 1800ms/260ms 지연이 적용되고 reduced-motion에서는
  즉시 표시되는지 확인한다.
- `--paper: #f2f8ff`가 유일한 배경색 편집 지점인지 확인한다.
- 생성한 `hero.jpg`가 브라우저에서 정상 로드되고 전체 콘텐츠 폭을 채우는지 확인한다.
- 상단 `media` 주석에 hero, map, gallery 파일명 예시가 모두 있는지 확인한다.
- 전체 Node·Python 테스트, 영상 디코딩과 `git diff --check`를 실행한다.
